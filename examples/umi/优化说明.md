# UMI数据转换脚本优化说明

## 问题
原始的 `convert_umi_data_to_lerobot.py` 脚本处理速度太慢，单进程顺序处理所有数据。

## 解决方案
开发了两个多进程版本，提供 **3-10倍** 的性能提升。

## 新增脚本

### 1️⃣ 并行版本（推荐大多数用户）
**文件**: `convert_umi_data_to_lerobot_parallel.py`

**特点**:
- 多进程并行处理
- 中等内存占用
- 3-5倍速度提升
- 稳定可靠

**使用方法**:
```bash
python convert_umi_data_to_lerobot_parallel.py \
    --input dataset.zarr.zip \
    --output ./output \
    --repo-id username/dataset \
    --workers 8 \
    --batch-size 100
```

### 2️⃣ 优化版本（最快速度）
**文件**: `convert_umi_data_to_lerobot_fast.py`

**特点**:
- 预加载数据到内存
- 优化的批处理
- 5-10倍速度提升
- 需要更多内存

**使用方法**:
```bash
python convert_umi_data_to_lerobot_fast.py \
    --input dataset.zarr.zip \
    --output ./output \
    --repo-id username/dataset \
    --workers 8 \
    --load-batch-size 50 \
    --process-batch-size 10
```

## 如何选择？

| 你的情况 | 推荐脚本 |
|---------|---------|
| 数据集小（<1000 episodes） | 原始版本 |
| 数据集中等（1000-5000） | 并行版本 ⭐ |
| 数据集大（>5000） | 优化版本 ⭐ |
| 内存有限（<16GB） | 并行版本 |
| 内存充足（>32GB） | 优化版本 |
| 首次使用 | 并行版本 ⭐ |


## 参数调优建议

### 根据CPU核心数
```bash
# 4核CPU
--workers 4

# 8核CPU
--workers 8

# 16核CPU
--workers 16
```

### 根据内存大小
```bash
# 8GB内存
--workers 4 --batch-size 50

# 16GB内存
--workers 8 --batch-size 100

# 32GB+ 内存
--workers 16 --load-batch-size 100
```

## 常见问题

### Q: 遇到内存不足怎么办？
A: 减小批处理大小：
```bash
--batch-size 50  # 或更小
--load-batch-size 25  # 或更小
--workers 4  # 减少进程数
```

### Q: 为什么速度没有提升？
A: 可能原因：
1. 数据集太小（用原始版本反而更快）
2. 使用机械硬盘（换成SSD）
3. workers设置过多（尝试减少）

### Q: 可以同时处理多个数据集吗？
A: 可以，但要注意资源分配。建议顺序处理或使用批处理脚本。

## 技术实现

核心优化点：
1. ✅ 使用 `multiprocessing.Pool` 并行处理
2. ✅ 预加载数据减少IO操作
3. ✅ 批处理策略优化内存使用
4. ✅ 增加图像写入线程数
5. ✅ 及时释放内存（gc.collect）
